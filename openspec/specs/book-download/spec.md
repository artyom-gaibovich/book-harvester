# book-download

## Purpose

Определяет наблюдаемое поведение утилиты скачивания книг с iprbookshop: как задаются учётные данные, как принимаются ID книг, как расшифровывается поток и куда и под каким именем сохраняется итоговый PDF.

## Requirements

### Requirement: Задание cookies через .env

Утилита SHALL брать строку cookies авторизации из переменной окружения `COOKIE`. Значение переменной MAY задаваться через файл `.env` в корне проекта. Утилита SHALL NOT читать cookies из файла `cookies.txt` и SHALL NOT поддерживать переменные `IPR_COOKIES`/`IPR_COOKIES_FILE`.

#### Scenario: Cookies заданы в .env

- **WHEN** в файле `.env` присутствует строка `COOKIE=<строка cookies>` и утилита запускается
- **THEN** запросы к iprbookshop выполняются с этими cookies

#### Scenario: Cookies заданы через переменную окружения

- **WHEN** переменная окружения `COOKIE` установлена в среде процесса (файл `.env` отсутствует)
- **THEN** используется значение из окружения, файл `.env` не требуется

#### Scenario: Cookies не заданы

- **WHEN** переменная `COOKIE` не задана ни в окружении, ни в `.env`
- **THEN** утилита завершается с понятной ошибкой, указывающей задать `COOKIE`, и не выполняет сетевых запросов

### Requirement: Ввод списка ID книг

Утилита SHALL принимать один или несколько числовых ID книг. При вводе нескольких ID они разделяются запятой. Нечисловые значения SHALL отбраковываться с сообщением, обработка остальных ID продолжается.

#### Scenario: Ввод нескольких валидных ID

- **WHEN** пользователь вводит `123, 456, 789`
- **THEN** утилита пытается скачать книги с ID 123, 456 и 789

#### Scenario: Среди ID есть невалидные

- **WHEN** пользователь вводит `123, abc, 789`
- **THEN** значение `abc` отбраковывается с сообщением о невалидном ID, а книги 123 и 789 обрабатываются

#### Scenario: Все ID невалидны

- **WHEN** ни один из введённых ID не является числом
- **THEN** утилита сообщает, что валидных ID нет, и завершает работу без скачивания

### Requirement: Скачивание и расшифровка книги

Для каждого валидного ID утилита SHALL получить токен доступа, расшифровать потоковый формат книги в PDF и продолжить обработку остальных ID при ошибке на одной книге.

#### Scenario: Успешное скачивание

- **WHEN** для ID есть доступ и поток корректен
- **THEN** поток расшифровывается в PDF и книга сохраняется

#### Scenario: Нет доступа к книге

- **WHEN** сервер не выдаёт токен доступа для ID (например, cookies устарели или нет подписки)
- **THEN** утилита сообщает, что книга не скачана, с причиной и переходит к следующему ID

### Requirement: Сохранение книги в каталог загрузок

Скачанные книги SHALL сохраняться в отдельный каталог загрузок (по умолчанию `downloads/`, путь MAY переопределяться переменной `DOWNLOAD_DIR`), а не в корень проекта. Для каждой книги SHALL создаваться отдельная папка с именем вида `<timestamp>_<slug>`, где `timestamp` — момент скачивания в формате `YYYYMMDDHHmmss`, а `slug` — транслитерированное в латиницу и приведённое к нижнему регистру название книги. Файл PDF SHALL помещаться внутрь этой папки.

#### Scenario: Папка книги создаётся с меткой времени и slug

- **WHEN** книга «Манифест инвестора: готовимся к потрясениям…» скачана 2026-08-23 17:37:44
- **THEN** создаётся папка вида `downloads/20260823173744_manifest-investora-gotovimsya-k-potryaseniyam/` и PDF сохраняется внутрь неё

#### Scenario: Название книги недоступно

- **WHEN** название книги не удалось получить
- **THEN** в качестве slug используется ID книги, папка всё равно создаётся с меткой времени

#### Scenario: Переопределение каталога загрузок

- **WHEN** задана переменная `DOWNLOAD_DIR=/custom/path`
- **THEN** папки книг создаются внутри `/custom/path`, а не в `downloads/`
